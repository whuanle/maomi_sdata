# dashboard — SOP

> 关联：[sdd](sdd.md) · [bdd](bdd.md) · [tdd](tdd.md)

- Go 验收：`go test -tags duckdb_use_lib ./cmd/sdata ./internal/query -run 'TestDashboard|TestCustomPanel|TestPrometheus'`。配置必须使用原协议的字符串 `configJson` 与 `kind=view`，不再接受旧 Go 占位实现的对象配置。冲突 409 需重新加载后保存；查询错误查看面板 `error` 与服务日志。

- 路由定位：`?edit=1` 为整盘编辑；`panels/new?kind=custom|explorer|group` 为新建；`panels/:panelId/edit` 编辑普通、自定义或分组成员，`preview` 为登录可用的只读预览。`tab`、`tab.<groupId>`、`node`、`settings=display` 保存界面位置，不保存查询内容。刷新恢复位置与已保存配置，未保存内容仍需整盘保存；离开编辑有确认。分组选择框须使用label，禁止把children透传原生input。
- 自定义组件：画布编辑态点击“自定义组件”进入独立设计页，默认选择来源、聚合与Lucene筛选，按时间桶/分类组织数据并添加引导式表达式；高级SQL仍可手工映射字段。运行成功后应用到草稿，最后整盘保存；查询变更必须重新运行。表达式仅引用前序节点，时间序列按完整键匹配，不自动补零；重复键需先在SQL聚合。节点结果可检查参数、字段、耗时与截断。未知版本不可覆盖；取消不修改原组件。
- 自定义组件验收：先修改画布名称/布局，再设计A/B及比率表达式，应用后确认原草稿保留；保存、刷新及再次编辑核对查询和展示；回归readonly、409、亮暗与窄屏。自动测试不替代登录后浏览器验收。
- Screens 已下线，旧 `/screens` 不重定向；API 仅服务 view，历史 screen 按 ID 返回 404。历史记录不自动删除或转换，清理须另行备份并授权。
- 端点：`GET/POST /api/dashboards`、`GET/DELETE /api/dashboards/{id}`、`GET /api/dashboards/{id}/data?rowLimit=&from=&to=`、`POST /api/dashboards/preview-panel`。
- 面板查询按 `query.kind` 分派：metric → MetricStore；dsl → 统一 DSL（字段/操作符白名单）；promql → PromQL 子集；sql → 分析执行器（只读约束同 analytics；含 `{{logs}}` 占位符自动展开区间内天表并绑定 $start/$end）。
- 面板协议 version=1：新增面板一律走前端编辑器（生成 query 对象）；手写 configJson 时旧协议（面板根挂 sql/queryId）仍兼容。
- 仪表盘轮询建议 ≥5s；rowLimit 控制单面板行数；maxSeries 控制序列基数（1–100，默认 20）。
- 面板查询错误以 PanelData.Error 内联呈现（不中断其它面板）；编辑器预览防抖 600ms 调 preview-panel。

- 数值面板：从 Explorer 保存后核对条件语法/原文、绑定参数、格式、别名、条件色及背景趋势；趋势按面板实际时间独立查询，刷新固定范围也应更新，失败不遮盖主值；核对重叠规则最后匹配、规则顺序和独立背景色。旧 stat 无配置仍可展示；SQL 改动后需重新配置 Explorer。专项验证见 `number.test.tsx`、`SaveChartModal.test.tsx`、`PanelCard.test.tsx`。
- Bar 面板：Explorer 运行后保存，检查分类排序/Top N 参数、数值格式及原布局；修改未运行条件不应影响保存。改变仪表盘时间范围重算全窗口聚合，不生成时间桶；与 Time Series 柱形模式分开验收。专项测试见 `bar.test.tsx`、保存与面板测试。
- 分布热力图：保存后核对数值尺度、桶数和计数色阶，改变时间范围后格数≤9600且统计仍为全量。旧配置缺尺度沿用线性；面板仅展示和悬停，下钻/框选进入 Explorer 验收。登录后补亮暗、小面板及保存重开，自动测试不能替代视觉验收。
- 图表复用入口：`@/design-system` 的 `TimeSeriesChart`；`unit/showLegend/zoom` 只影响展示，不改变后端查询。亮暗色取自 `useCssTheme`，不要另引图表 UI 库。
- 图表验收：`cd ui && npm run test && npm run build`；浏览器检查亮暗图例、单位、缺口和小面板尺寸，测试通过不替代交互验收。
- Search/Patterns 面板：保存后核对事件表分页、内部列隐藏及模式趋势/模板展示；模式详情与事件续页在 Explorer 中进行。回归 `PanelCard.test.tsx`，真实保存重开仍需登录测试账号验收。
- MQTT 遥测：选择 MQTT（设备遥测），按 device_key/signal 筛选或分组，数值默认 avg(num_value)，字符串事件使用 str_value。运行后保存并重开核对来源、参数和定义；内部仍为 iot / {{iot}}，包括 HTTP 遥测，不迁移设备台账，不扩展热力图。
- 饼图四来源回归：逐一运行 Logs/Traces/Metrics/Sessions，修改未运行分类后应用到画布，再编辑应恢复执行配置；Metrics 核对指标名、标签路径/过滤和 Delta，原图例关闭状态及布局必须保留。修改仪表盘时间应重算窗口聚合；组件测试不替代登录后完整保存重开验收。
- 饼图面板：从 Explorer 运行后保存，核对分类上限、数值格式及序列覆盖；旧面板缺设置时使用默认格式。全零不绘制比例，含负值时回 Explorer 修正聚合；显示上限只取返回结果中的最大分类。真实保存重开验收需同时核对原有布局。

- 协议检查：新面板 query/visualization/editor 分别负责执行、展示和恢复；Number 趋势在 query.numberTrend。旧 explorer 只经适配读取，加载不迁移。验收移除 editor/explorer 后展示保持、连续两次兼容编辑不丢类型/布局、只改展示不重查、修改 rowLimit 触发草稿预览；未知定义提示后不可覆盖，不手动删除版本字段绕过校验。
- 添加图表：在共享工作区配置并 Run，再点底部“应用到画布”直接应用，无需二次确认或填写指标查询；未运行、查询中、失败或切到无结果页签时底部按钮禁用；新建入口不提供旧高级侧栏。已有 metric/DSL/PromQL 和 Markdown 面板仍使用兼容编辑器，不能把旧侧栏的空指标校验当作 Explorer SQL 执行失败。
- 共享编辑：画布“添加组件/编辑”打开图表工作区；运行后“应用到画布”只更新草稿，仍需整盘保存。重新编辑应恢复原始筛选、粒度和公式；旧 SQL 缺定义时提示兼容模式，不反向猜测 Builder。高级入口保留 metric/DSL/PromQL 与 Markdown。
- 编辑闭环验收：添加 A/B 与公式→运行→应用→拖拽缩放→整盘保存→刷新→重开，检查定义、显示配置、坐标和尺寸。窄屏布局只用于查看，不写回桌面坐标；自动测试不能代替真实浏览器验收。
- 紧凑头部验收：详情首行距内容区顶部约 8px，名称、操作和查询控件共用一行工具栏，时间范围、自动刷新及运行依次放在展示按钮后，查看态“编辑面板”紧跟运行按钮，空间不足时自然换行；取消、保存、展示应紧跟名称输入框靠左排列，修改草稿后提示不得挤开操作；详情编辑页不再展示描述输入框，已有描述数据保持不变。检查长名称、窄屏换行、亮暗主题及查看/编辑/展示模式无横向溢出。列表与其他页面仍保留原间距；运行、保存/取消、只读权限及草稿离开确认须回归。
- 工作流入口：`/dashboards`（列表/新建）→ `/dashboards/:id`（画布编辑）→ `/dashboards/:id/present`（展示模式）。`/metrics` 已重定向。
- 导入导出（2026-11-20）：列表页「导入」选择文件或粘贴整盘 JSON（包装格式 `kind=sdata-dashboard`），名称/描述按文件预填可改，确认即创建并刷新列表；卡片与详情工具条「导出」下载 JSON，详情导出为当前草稿所见即所得。编辑态「导入面板」选择或粘贴面板 JSON，以新 id 追加画布底部，整盘保存后生效；分组导出含全部子面板，导入自动重映射子面板 id 与默认标签。解析失败或格式不受支持时不落库、不改画布；readonly 仅可见导出。后端无新端点，导入保存与整盘保存共用校验（非法结构 400）。
- 分组：编辑态“添加分组”只填名称即可创建空Group，不选择成员或默认标签。后续将组件拖至Group中央，高亮后松手加入；边缘仍用于布局排序。编辑Group可手动添加、移出并上下排序，移出最后成员保留空Group；解散保留成员，删除容器及全部成员需确认。Group整体拖动缩放；只读/展示可切换标签但不可修改。保存后使用布局v3，旧客户端不可覆盖。
- 重叠拖曳：标题拖动到目标前后时邻居实时让位、占位框预览落点，松手才提交排序；来回拖动应立即恢复而不累计挤远，组件保持各自尺寸；同一网格内细微移动不重复计算排序，拖动项与占位框无位置过渡，仅邻居保留短transform动画；空白落点直接放置，无关留白不压缩。验收异尺寸连续前插/后插、缩放、Tab点击不拖动、保存刷新和窄屏不写回；自动测试不代替真实鼠标交互。
- 布局版本：v2 带 x/y；打开旧配置自动迁移显示，只有点保存才升级存储。configJson 校验失败会以 400 拒绝保存。
- 布局引擎 react-grid-layout 仅允许在 `design-system/DashboardGrid` 内生成定位样式（AGENTS 例外条款）；画布行高 96px、间距 12px，新组件最小 2×2、max h8；合法 v2 历史 1×1 尺寸保持。窄屏只读重排，不写回桌面坐标。
- Explorer 保存：运行后打开 Run 旁菜单→保存到仪表盘→选择目标→确认；核对旧面板与布局保持、过滤参数与图例保持。409 表示目标已改变，应重新读取再保存；不要盲目覆盖。Auto 粒度会随仪表盘查询时间跨度重新绑定。
- 公式保存验收：先运行有效公式，再保存到目标；重开检查公式/参数、输入显示开关和旧布局。缺失值与除零不能显示为 0；结果截断需缩小时间范围或分组数量。直接修改 SQL 后 Explorer 公式元信息失效，重新配置公式应回图表探索页。
- Markdown：图表探索切换 Markdown，直接输入正文并从预览下方菜单保存，无需 Run；仪表盘编辑抽屉可修改正文。空正文允许保存，上限 50000 字符。验收标题/列表/表格/代码块、亮暗主题及重开后的正文；原始 HTML 不渲染，危险链接不跳转。
- 草稿原则：拖动/缩放/增删改不触发查询重跑和落库；保存失败草稿保留。仪表盘展示要求已保存版本。

- Table：在 Explorer 运行后保存，面板 rowLimit 与 Top N 一致；修改未运行草稿不改变保存查询。检查 `explorer.tableQuery/tableColumns/tableSettings` 和查询参数，切换仪表盘时间后重算。格式、斑马纹和吸顶复用 ChartTable；旧无配置面板保留兼容。浏览器保存重开须使用测试账号验收。

- Table结构化筛选：默认排行或错误预设运行后保存；先确认生成SQL中的筛选值是参数，保存与下钻应包含同一参数字典。未运行草稿由提示区标明，不应改变旧结果或面板查询。
